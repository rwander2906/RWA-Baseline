# Releases & Versioning

Anwendungsprojekte verwenden eine nachvollziehbare Versionierung; Semantic Versioning wird empfohlen.

Ein Changelog unterscheidet mindestens noch nicht ausgelieferte Änderungen von veröffentlichten Versionen. Aufgenommen werden sichtbare Features, Verhaltensänderungen, relevante Bugfixes, Security-Änderungen, Breaking Changes sowie wichtige Betriebs-/Deployment-Änderungen.

Build- und Release-Artefakte sollen reproduzierbar erzeugt werden. Nutzerpakete enthalten die für Betrieb und Nutzung erforderlichen Dokumente und neutrale Beispielkonfigurationen, jedoch keine kundenspezifischen Daten oder Secrets.
